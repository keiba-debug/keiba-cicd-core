# 競馬5冊 横断統合 → ML特徴量 統合設計

> 司令塔Claudeが直接執筆(ローカルLLMではない)。各冊のML特徴量specを横断し、KEIBA-CICDの予測モデルに載せる
> **1つの特徴量体系**へ統合する。型: 対比表 → 因果パイプライン → 統合特徴量 → 実装順 → 限界 → 次の一手。
> 元ネタ: [[レース質マトリックス_ML特徴量]] / [[レース質マトリックス_実践編_ML特徴量]] / [[上がりXハロン_ML特徴量]] / [[展開読み_ML特徴量]] / スマート出馬表(亀谷)。

---

## 1. 5冊の役割対比 — それぞれ「どの軸」を担うか

| 書 | 著者 | 担う軸 | 出力 | 性質 |
|---|---|---|---|---|
| **双馬式 展開読み** | 双馬毅 | **展開(入口)** | テン1F→隊列・想定ペース | データ生成器(他の入力を作る) |
| **レース質マトリックス**(本編/実践) | 立川優馬 | **環境(レース質)** | 4軸2択ラベル(枠/脚質/ローテ/ペース) | ルールエンジン+黄金パターン決定表 |
| **上がりXハロン** | 安井涼太 | **能力** | スピード/スタミナ/パワーの3軸 | 能力測定(クラス/馬場/距離で標準化) |
| **スマート出馬表**(血統ビームvol.5) | 亀谷敬正 | **ノイズ除去/出口** | 人気ランク別集計・コース傾向×直近傾向 | バイアス補正・妙味の方法論 |
| **競馬場と前走位置取り** | みねた | **展開の実装版/EV** | 前走通過順≤3→front_ratio→pace、コースパターンA-F、期待値選別 | JRDB実装容易・[[競馬場と前走位置取り_ML特徴量]] |

**1行で**: 「**展開**で隊列を当て(双馬)、**レース質**で有利属性を決め(立川)、**能力**を環境で割り引いて測り(安井)、**人気ランク別**でノイズを除いて妙味を出す(亀谷)」。

---

## 2. 因果パイプライン(背骨) — 入口から出口へ

```
①展開[双馬式]  各馬 tenF1_best(距離補正) → 想定隊列(誰が前)→ pace_scenario / lead_side
                  + ext_pedigree_score(延長血統) → ローテ適性
        │  （レース質マトリックスは「ペース」を入力として要求 → ①がそれを埋める）
        ▼
②環境[レース質]  馬場状態(クッション値/含水率/上がり3F差)・コース定数・①のpace → 4軸2択レース質ラベル
                  + golden_pattern_id(条件→ラベル決定表35件)・非定常性(枠バイアスは近3年窓)
        │
        ▼
③能力[上がりX]  上がり2F/1F/4F → スピード/スタミナ/パワー(クラス・馬場・距離で標準化)
                  ★①のpace_scenarioで **ペース交絡を除去** (上がりは前半ペース依存)
                  + course_demand(場×距離の能力要求)との内積=適合
        │
        ▼
④出口[亀谷]    人気ランク別に集計してノイズ除去 → 過去傾向×直近傾向でコースバイアス確定
                  → 「勝率」と「妙味(EV)」を分離（安井§4の妙味の罠と同じ思想）
```

**キモ**: ①の `pace_scenario` が②のペース軸と③の交絡除去の**両方**に効く。展開予測が体系全体の上流。

## 4. 実装順序(段階導入・各段で検証)

1. **データ確認**: JRDB(`data3/jrdb`)に **テン1F/3F(前半ハロン)・上がり1F/2F/4F・クッション値・含水率** があるか棚卸し。無い列は通過タイム/コーナー通過から近似。
2. **展開ピース先行(最短入口)**: まず **`front_ratio`(前走3角通過順≤3の占有率／JRDBにある)** で `pace_scenario` を試作。閾値<30%=緩む/内枠先行有利・>40%=上がる/差し有利(みねた)。テン1F入手後に双馬式 `tenF1_best` で精度上乗せ。コース辞典の脚質別回収値で方向検証。
3. **レース質ラベル**: ①枠②脚質だけで全レース付与→効果検証→③④追加。`golden_pattern_id` は信頼度高い数本(東京芝2000/阪神中距離/小倉ダ1700/芝発走ダート)から。
4. **能力3軸**: 標準化定数(安井§2)を**JRDB実データで再回帰**→`ability_*`→`ability_deconfounded`(②のpace使用)。
5. **非定常対応**: `keibajo_course_bias_long.csv` を**年次分割**しrecency版に(枠バイアス経年反転)。
6. **妙味分離**: 「勝率モデル」と「EV/妙味モデル」で特徴量を使い分け(安井§4・亀谷)。生の上がり3F順位や人気は勝率には効くが妙味では織り込み済み。

---

## 5. 限界・リスク(必読)
- **非定常性**: 馬場造形で枠バイアスが**経年で符号反転**(立川実践§4: 2018-20内枠→2021-外枠)。固定長期集計は毒。**近3年窓・レジーム分割必須**。双馬/安井のデータも2015-2022基準で古い。
- **データ可用性**: テン1F・上がり1F/4Fは**JRA非公表**。JRDBや独自計算が要る。無いと展開・能力ピースが作れない=最大の前提リスク。
- **リーク**: すべて「対象レースより前」の走から。`pace_scenario`は確定枠順+出走馬の過去テンで事前計算(結果不使用)。
- **妙味≠勝率**: 上がり3F順位・人気は勝率に効くが**EVでは織り込み済み(回収<100%)**。価値は「市場が見ていない残差」(標準化後の能力・テン・反レース質)に宿る。
- **OCR目安**: 各specの数表(補正定数・閾値・枠別成績)はVLM由来。実データで再キャリブレ前提。
- **二重計上注意**: 立川のペース判別5要素①と双馬のtenF1集約は**同じものを二度入れない**(双馬版に一本化推奨)。馬キャラ(通過順由来)と能力3軸(上がり由来)は別系統なので両立可。

---

## 6. 次の一手
1. **JRDB列の棚卸し**(テン/上がり分割ハロン・クッション/含水率)→ 使える特徴量を確定。
2. `pace_scenario`(双馬)→ レース質ペース軸 → `ability_deconfounded`(安井) の**最小縦串**を1本通してオフライン検証。
3. 効果が出たら `golden_pattern_id`・`umachara_prob`・`frame_bias_3yr` を順次追加。
4. 既存 `data3/ml` の特徴量パイプラインに段階マージ。`keibajo_course_*.csv`(コース辞典)を事前バイアスの土台に。
5. PLG等の非競馬本は別系統(FBiz収益化)へ。本統合は競馬MLチーム用。
