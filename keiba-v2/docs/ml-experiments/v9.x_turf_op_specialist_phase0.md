# v9.x Regulus（レグルス）— 3歳上芝OP以上 専用モデル / Phase 0-1 検証 (Session 177 / 2026-06-26)

> **モデル名 = regulus（獅子座α「小さな王」, Stars系/馬単位）**。役割=経験豊富な王者級の馬の対決で軌跡(上昇/下降)を軸に勝ち負けを見抜く。命名体系 [[multi-model-naming]]。

> **結論先出し**: 芝OP+ クラス特化モデルは **NO-GO**。同一特徴量の汎用モデルに精度(AUC)・較正(ECE)で勝てない。
> 派生で「本番モデルを現行特徴量で再学習すべきか」も検証 → **再学習も不要**(ROIで live v2.3 ≈ fresh)。
> 関連: `market_calibration_edge_map.md`(OP市場はシャープ), `niche-specialist-strategy`(nova_emerging=低クラスで同結論), `niigata-1000m-project`(②横展開)。

## 0. 動機 (ふくだ S177 仮説)
> 芝OP以上は未勝利/条件と違い、出走馬の**過去走実績データが豊富**なので特徴量をより有効活用できるはず。
> 特徴量重要度の構成も変わり、クラス特化で予想精度が上がるのでは。芝重賞は毎週組まれ**利用頻度も高い**。

nova_emerging(Session 121) は **低クラス(1勝/新馬=データ希薄)** で「クラス特化は polaris を超えない(市場同調)」を確認済だが、
**高クラスは未検証**。ふくだ仮説はそのギャップを突く。S173 より「OP市場はシャープ=精度ではROIエッジ出ない」想定なので、
本検証の狙いは **払戻エッジでなく『予想品質(本命精度・較正)が上がるか』**。

## 1. 手法 (交絡を排した apples-to-apples)
- **重要な落とし穴**: live polaris v2.3 は **152特徴量**だが現行 `FEATURE_COLS_ALL` は **212特徴量**(v2.3以降に過去走/コメント系60個追加)。
  そのまま比較すると「特化の効果」と「特徴量60個差」が混ざる。
- → **同一212特徴量・同一期間・同一cutoffで『汎用GEN(全データ学習)』と『特化SPEC(芝OP+学習)』を両方フレッシュ学習**し、
  **両方とも同じ芝OP+ test 行**で評価。これで純粋に「特化したことの効果」だけを抽出。
- split: train 2020–2025.03 / val 2025.04 / **test 2025.05–2026.05 (13ヶ月OOS)** / sire-cutoff 2025-03-31(リークフリー)。
- 芝OP+ = `track_type==turf ∧ grade∈{OP,Listed,G1,G2,G3}` = **655レース / 8,417頭** (OP5833/G3877/L697/G2553/G1457)。
- GEN train=241,364件 / SPEC train=41,874件 (芝OP+は全体の~17%)。
- スクリプト: `ml/nova/train_turf_op.py` (`--target both`, GEN+SPEC×P/W=4モデル)。

## 2. 結果① 精度・較正 (芝OP+ test, GEN vs SPEC)
| target | 指標 | 汎用GEN | 特化SPEC | 差 |
|---|---|---|---|---|
| W | AUC | **0.7678** | 0.7543 | -0.0135 (特化が明確に悪化) |
| W | ECE(cal) | **0.0118** | 0.0252 | +0.0134 (特化が悪化) |
| W | top1勝率 | **27.2%** | 26.3% | -0.9pt |
| W | 単勝ROI | 80.2% | 86.5% | +6pt (※勝率↓×的中odds↑のノイズ・両方<100%) |
| P | AUC | **0.7742** | 0.7695 | -0.0047 (汎用やや上) |
| P | ECE(cal) | **0.0146** | 0.0201 | +0.0055 (汎用やや上) |
| P | top1勝率 | 28.2% | 27.9% | -0.3pt |

→ **特化は精度(AUC)も較正(ECE)も汎用に勝てない。** ROI微増はノイズ(W的中 178→172, 両方<100%, S173通りOP市場シャープ)。

## 3. 結果② 特徴量重要度シフト (仮説の直接検証)
| target | 過去走系シェア GEN→SPEC | 主な変化 |
|---|---|---|
| W | 65.0% → 61.7% (**-3.3pt**) | `avg_finish_last3` 7.13%→0.64%(激減)・`jockey_win_rate`↓ / `track_type_top3_rate`・`jrdb_cid_score_avg3`↑ |
| P | 25.0% → 29.5% (**+4.5pt**) | `jrdb_cid_score` 47.4%→41.0%(依然支配) / `dam_sprint_top3_rate`・`jrdb_cid_score_trend`↑ |

→ **重要度は確かにシフトする**(仮説の半分は当たり)が、**精度には繋がらない**。

### なぜ特化が負けるか (高クラス版の理由)
OP+だけだと「直近着順」「騎手勝率」「前走人気」など**クラス跨ぎで一番効く強信号が、皆強い馬の中では弁別力を失う**
(`avg_finish_last3` の激減がそれ)。それを置き換える OP+ 専用の強信号は無い。加えて学習データが **241k→42k(6分の1)**。
= nova(低クラス)と同じ **「データ量 > クラス純度」** の結論が、理由は違えど高クラスでも再現。**今回は仮定でなく実測で確定。**

## 4. 派生検証: 本番モデル再学習は必要か (full test 3653レース)
検証中、fresh GEN(212) が live v2.3(152) を **P top1勝率で大きく上回った**(下表)ため、本番再学習の要否を厳密検証。
| target | 単勝ROI live→fresh | top1勝率 live→fresh |
|---|---|---|
| P | **82% → 78%** (liveが上) | 19.7% → 29.9% (10pt差・本物) |
| W | 80% → 79% (互角) | 28.8% → 29.0% (互角) |

- **賭けの指標=ROIで見れば live ≈ fresh(P はむしろ live微優)。W は完全互角。**
- P勝率10pt差は「fresh P=人気寄り本命を引く(勝率↑/odds↓/ROI↓)」vs「live P=中オッズ複勝堅実馬を上位に置く(勝率↓/odds↑/ROI↑)」の
  **性格差であって品質差でない**。→ **本番再学習は不要**(live v2.3は13ヶ月OOSのROIで fresh と同等)。
- スクリプト: `scratchpad/eval_fresh_vs_live.py`。

## 5. 結論と次の一手
1. **①芝OP+専用モデル = NO-GO** (精度・較正で汎用に負ける/市場シャープ/データ量負け)。
2. **本番再学習 = 不要** (ROIで live ≈ fresh)。
3. **残る本物の構造エッジ = ②新潟芝1200**: 機会スキャン(13ヶ月OOS)で**ローカル芝短距離で唯一、千直級の枠バイアス**
   (外/内 top3率比 **2.86**, 内8.8%→外25.2%; cf. 千直3.20)を保持。他のコーナー有り1200(函館0.80/福島1.08/小倉0.89)はバイアス弱。
   → 新規コースでなく **vega-niigata1000 ルールエンジンの 1200/1400 拡張**として実装するのが筋。
4. (補足) 重要度シフトの知見(OP+では直近着順より適性/CIDトレンド/騎手コース相性が効く)は、専用モデルでなく**ナラティブ/印**に活用可。

## 6. Phase 1: 方向転換 — 「3歳上芝OP+ 専用モデルを地道に研ぐ」(ふくだ S177)
> Phase 0 で「同特徴量のクラス特化」は NO-GO。だが ふくだ指摘「**情報ゼロの新馬と、経験豊富で上昇/下降の比較材料が多いOP+で結果が変わらないのはモデルの弱点**」+
> 「**指標で負けても経験馬の対決に最適化した専用モデルで張りたい**」([[feedback_specialist_for_its_own_sake]]) を受け、目的を
> 「汎用に勝つ」→「**3歳上芝OP+ 専用モデルを最高に研ぐ + 何が効くか掴む**」へ転換。スコープ = 3歳以上(age>=3, 2歳除外) × 芝 × OP以上。

### 6.1 クラス別AUC = 高情報クラスで識別力が低い(伸びしろの傍証)
live model 13ヶ月OOS の W_AUC: 未勝利 0.814 / 1勝 0.779 / **OP 0.767 / Listed 0.694 / G3 0.735**。
情報が多いはずの OP/L/G3 で識別力が低い = 「拮抗で難しい」+「**高情報を活かしきれてない**」の両方。後者に伸びしろ。

### 6.2 アブレーション(前向き積み上げ) — 軌跡が #1 レバー
`ml/nova/ablation_turf_op.py`(splits を1回 build→pickle 化し特徴量サブセット総当たり)。3歳上芝OP+ 611R eval。
**グループ単独パワー(basic からの AUC 上昇):**
- **W: 🥇trajectory +0.0227(ソロROI 90%) / 🥈jockey +0.017 / 🥉form +0.015。pedigree は basic より悪化(-0.004)。**
- **P: 🥇jrdb_cid +0.061(CIDが複勝の支配項) / 🥈jrdb_other +0.037 / 🥉trajectory +0.034。pedigree 悪化(-0.009)。**
- **両target で軌跡(rising/declining)はトップ3・血統(priors)は悪化** = ふくだ仮説「経験馬は実績で見る/priorsは捨てる」が定量立証。

### 6.3 リーンモデル確定 (`scratchpad/lean_turf_op.py`・構成はドメイン論理で固定=test探索なし)
| target | 構成 | n_feat | AUC | ROI |
|---|---|---|---|---|
| W | 全特徴量 | 198 | 0.7520 | 70% |
| W | **lean_plus** | **103** | **0.7574** | 80% |
| W | lean_core(軌跡/指数のみ) | 83 | 0.7384 | **86%** |
| P | 全特徴量 | 212 | 0.7692 | 77% |
| P | **lean_plus** | **117** | **0.7701** | 82% |

- **lean_plus(basic+form+trajectory+jrdb_idm+jrdb_cid+jrdb_other+jockey+pace+class_ctx) = 約半分の特徴量で全部入りに並ぶ/微増**。
- 血統+ノイズ群(pedigree/trainer/comments/misc)を落とすだけ(drop_priors)で両target改善 → 高情報クラスで priors はノイズと確定。
- lean_core(最も削った構成)が ROI/勝率最高 = 人気寄りに過適合しない。

### 6.4 Phase 1 結論
- 経験馬専用の"鋭い道具"の正体 = **lean_plus 構成(軌跡/CID中核・血統排除)**。「クラスで絞る」でなく「**何を見るかを経験馬向けに最適化**」が正解。
- 次の積み上げ候補: 新規**軌跡特徴量**(クラス相対の上昇度/ペース補正フォームトレンド/「このクラスで上がり目」)を設計してアブレーションに追加。

## 7. Phase 2-B: レース文脈で過去走を"掃除"して能力トレンドを de-confound = **NO-GO** (Session 178 / 2026-06-28)
> Phase 2-A で「生 front_ratio 足し」は incremental AUC ≒ 0(冗長)と判明。本丸 B = **過去走を「文脈不利度」で採点し、不利文脈の走を割り引いて能力トレンド(`idm_trend`/`ls_idx_trend`)を作り直す → 素トレンドを置換して AUC が上がるか**。成功基準 = **置換で AUC ≥ +0.005**(611R単発ノイズ超え)、同等以下なら畳んで学び記録。

### 7.1 ★決定的 de-risk: JRDB IDM は既に文脈で掃除済み (R²=0.9999)
着手前に `jrdb_sed_index`(各過去走の SED)を実査したところ、IDM 素点が**ペース/トラブル/位置取りの補正フィールドを既に内包**していた。`idm ~ soten + 各adj` の線形回帰:

| 成分 | 係数 | | 成分 | 係数 |
|---|---|---|---|---|
| soten(素点) | **+1.00** | | ichi_tori_adj(位置取り) | **+1.00** |
| pace_adj(ペース) | **+1.00** | | furi_adj 系(道中不利) | 計 **+1.0** |
| deokure_adj(出遅れ) | **+0.99** | | race_adj | **+1.00** |

→ **`IDM = 素点 + ペース補正 + 出遅れ + 位置取り + 不利 + レース補正` がほぼ恒等式 (R²=0.9999 / 残差std=0.15 vs idm std=17.7)**。
書籍法(みねた front_ratio・安井 上がり3軸)が lap_times から一から再構成しようとしている「ペース文脈での割引」は、**JRDB が IDM 内で既に(より正確に)実施済み**。これは Phase 2-A で生 front_ratio が効かなかった理由とも整合。`agari_idx`/`ten_idx` も SED に存在 → 上がり3軸の lap 再構成も冗長。

### 7.2 軽量 idm_trend_clean を構築して swap 検証
重い lap-cache/上がり3軸エンジンは建てず、**IDM に入っていない唯一の文脈 = front_ratio×脚質の構造的ミスマッチ(corners由来・安価)**のみで掃除する軽量版を実装:
- `front_ratio`(全36,190レース)を horse_history_cache の corners からリークフリー計算(前走3角≤3占有率)。
- `struct_disadv`(符号付) = front_ratio帯(<0.30 先行有利 / >0.40 差し有利) × 自馬脚質。不利文脈=+ / 有利文脈=−。
- `idm_clean[i] = idm[i] + α·struct_disadv(i)` → `idm_trend_clean = clean[-1] − mean(clean[-5:])`(jrdb_idm_trend と同式)。α∈{0,2,4,8}。
- 配線検証: α=0 の再現 `idm_trend_repro` が既存 `jrdb_idm_trend` と **corr=1.000 / MAE=0.00** → パイプライン忠実。

### 7.3 swap-ablation 結果 (3歳上芝OP+ 611R / 3seed平均)
| variant | W AUC | ΔvsBase | P AUC | ΔvsBase |
|---|---|---|---|---|
| **base (lean_plus)** | **0.7585** | — | **0.7699** | — |
| drop_ls(置換なし) | 0.7533 | −0.0052 | 0.7708 | +0.0009 |
| swap_ls→idm_trend(α0=掃除なし) | 0.7475 | −0.0110 | 0.7705 | +0.0006 |
| swap_ls→clean_a4 | 0.7468 | −0.0117 | 0.7680 | −0.0019 |
| swap_ls→clean_a8 | 0.7493 | −0.0092 | 0.7701 | +0.0002 |
| swap_ls→agari_idx_trend | 0.7482 | −0.0103 | 0.7688 | −0.0011 |
| **swap_idm→clean_a4**(素idm_trendをcleanに直接置換) | 0.7561 | **−0.0024** | 0.7702 | **+0.0003** |
| add clean_a4(生足し) | 0.7451 | −0.0134 | 0.7687 | −0.0012 |

### 7.4 Phase 2-B 結論 = **掃除は素トレンドを超えない (NO-GO)**
1. **掃除(α=2/4/8) ≈ 掃除なし(α0)**: W 0.7468–0.7493 / P 0.7680–0.7701、いずれも α0 と ±0.0025 以内 = ノイズ。`swap_idm→clean_a4` の直接置換も W −0.0024 / P +0.0003 = 不活性。**構造的 front_ratio 掃除は idm_trend に何も足さない**。
2. **`jrdb_ls_idx_trend`(W#1柱)は置換不能**: idm系トレンドに差し替えると W は一律 −0.009〜−0.012 悪化(LS指数=JOA由来の別系統シグナル)。P では ls_idx_trend 自体が不要(全変種 ±0.002 のノイズ・#1柱は CID)。
3. **生足し(add)も無駄**: W −0.0134(seed分散±0.0197)、Phase 2-A と一致。
4. **三重の独立確認**で「OP+ の能力トレンドは既存 JRDB 特徴量で十分 de-confound 済み」: (a) IDM回帰 R²=0.9999、(b) Phase 2-A 生front_ratio≒0、(c) Phase 2-B swap=ノイズ。市場/JRDB がシャープな OP+ では書籍法の掃除に残差αは無い([[market_calibration_edge_map]]「OP市場シャープ」と整合)。
5. **重い book-engine(lap-cache・上がり3軸標準化再回帰)は建てない**=IDM が既に持つものの再発明。労力を残差の薄いここに投じない([[feedback_long_term_right_way]]/[[feedback_proactive_debt_paydown]])。
6. **次に残差がありそうな唯一の方向** = §6.4 の「**クラス相対の軌跡**」(絶対IDMでなく "このOPクラスで上昇中か" の相対トレンド)。IDM の文脈掃除は済んでも「クラス内相対位置の変化」は別軸で未捕捉の可能性 → B の次の候補(B')。

## 8. craft 成果物: 脚質・能力プロファイル `leg_profile.py` (印/解説用・Session 178 ふくだ採択)
> Bの掃除はNO-GO だが「経験豊富な王者級の馬の**脚質・能力タイプを言語化して印/解説に出す**」のは payout でなく**説明力**として別価値([[feedback_specialist_for_its_own_sake]])。ふくだ採択。
- `ml/nova/leg_profile.py`: 安井の上がり3軸を **lap_times 再構成でなく JRDB SED の正規化済み指数で軽量表現**。リークフリー(対象日より前の最近5走):
  - **テン力**=`ten_idx`(前半/先行力) / **上がり力**=`agari_idx`(瞬発/末脚) / **持続力**=`front_3f − rear_3f`(馬の自走前後半3F・後半垂れない=スタミナ)。各軸を**偏差値(平均50・SD10)に指数化**(ふくだ要望)+S/A/B/C/D。脚質=corners(道中位置/頭数)→逃げ/先行/差し/追込。上昇度=`joushou_code`。
  - 言語化タグ: 末脚一閃型(展開待ち)/先行押し切り型/バテない持続型(消耗戦◎)/オールラウンダー/上昇気配。
- **web予想ページの馬カードに配線**(表示専用・買い目に影響しない): `leg_profile.py --emit-date YYYY-MM-DD` が `races/Y/M/D/leg_profiles.json`(race_id→umaban→profile)を生成 → reader `enrichPredictionsWithLegProfiles` が umaban 突合でマージ → race-card に「脚質/3軸」列(偏差値3つ+脚質+tagツールチップ)。entry の86%に付与(残=新馬/初出走で過去走なし)。tsc src 0。
- 日次運用: prep Phase② に `python -m ml.nova.leg_profile --emit-date <翌開催日>` を足すと自動生成(未配線・現状は手動 emit 済=2026-06-27/28)。
- B' 候補(クラス相対の軌跡)もこの leg_profile 上に乗せられる(クラス内偏差値化)。
