## 2. 2つの確定事項

### 2.1 金額 = 基準金額 × レート（ふくだ確定）

今の本番は「1レース上限 = 3,000円固定」で、基準金額（入金額・残高）と連動していない。
これを **基準金額 × レート** で動くようにする。

| 用語 | 中身 | 今の値 |
|---|---|---|
| 基準金額 | `daily_start_balance_yen`（本日のスタート額＝入金額） | 30,000円 |
| 通常レート | 普段のレースに張る割合 | **5%**（→ 1,500円） |
| 勝負レート | 勝負条件のレースに張る割合 | **15%**（→ 4,500円） |

- 1レースの上限（per_race_cap）= 基準金額 × レート。
- 基準金額を変えれば全レースの賭け金が自動で連動する（入金額を下げた週は賭け金も下がる）。
- ★今の暗黙レート＝ 3,000 ÷ 30,000 ＝ 10%。それを通常5%に下げ、勝負を15%に上げる（3倍差）。

### 2.2 勝負条件 ＝ 単勝一本の4条件（検証で確定）

`tansho_H`（[simulate_strategy_redesign.py](../ml/simulate_strategy_redesign.py)）:

| 条件 | 意味 |
|---|---|
| ◎が勝率1位（rank_w=1） | AIのWinモデルで1位 |
| 人気とのズレ≥3（win_vb_gap≥3） | 市場人気よりAI評価が3ランク以上高い＝妙味 |
| EV≥1.3（win_ev≥1.3） | 単勝の期待値が1.3倍以上 |
| 着差≤60（predicted_margin≤60） | 接戦すぎない（勝ち切れる） |

- 今のデータで **197件・月15件・1日1.66レース・的中11.7%・単勝Flat ROI 108.3%**。
- 中身は **5〜19倍のソコソコ人気の本命が9割**。「当たればデカいが当たりが薄い」型。

## 3. 勝負レートで何をするか（検証で確定）

### 3.1 単勝は勝負Rだけ・厚く

| 単勝の張り方 | 収支 | ROI |
|---|---|---|
| ◎単勝を毎レース（薄く広く） | -65,800円 | 85.8% |
| **勝負R（197件）だけ単勝** | **+9,780円** | **108.3%** |

→ 他レースで単勝を薄く張っても全体を食う。**単勝は勝負Rだけ**が唯一プラス。

### 3.2 複勝は足さない（保険にならない）

勝負R（単勝600円）に◎の複勝を足すと:

| 複勝額 | 収支 | ROI |
|---|---|---|
| 0（単勝のみ） | **+9,780円** | **108.3%** |
| 300円 | -4,680円 | 97.4% |
| 600円 | -19,140円 | 91.9% |

→ 足すほど赤字に向かう。単勝外れ時に複で取り返せたのは複600円でも174回中20回だけ
（◎の複勝が安すぎる）。安定感（月別ばらつき↓）の代償が黒字の消失。**複勝は足さない**。
本番v2「複勝はメインから外す（キャラへ移譲）」と完全一致。

### 3.3 他のレース（勝負条件でない）

- 単勝は買わない（◎単勝は -EV のことが多い＝§3.1 で毎レース薄い単は -65,800円）。
- combo（馬連〜三連単）に通常レートの cap を ★フルに回す★（Session 167 修正）。
  - 抜いた単勝(-EV)分を浮かせず +EV の combo（EV比例で買う点のみ）に回す。「通常R は combo
    しか買わないのだから cap で combo を買うのが自然」（ふくだ）。浮かせる(0 EV)より良い。
  - combo は EV 比例＋100円単位なので cap ぴったりにはならず端数（〜100円）は浮く。
    -EV の点（wide/三連複/三連単が EV floor 未満）には回らない。
  - 実例: 東京2R（2026-06-20）通常cap1,700 → 馬連+馬単で1,600（端数100浮き）。
    旧版（v2委譲→単勝除外で単勝share分を浮かせる）は1,400だった。
- ★見送りはしない★（Session 162-165 で見送りゲートは3回とも害確定）。

### 3.4 combo 内の配分方式（Session 168・天井変種を実データ検証して採用）

★きっかけ★: ふくだ「馬券の買い方が保守的すぎる。回収率1000%超を基本方針にしないと改善しないのでは」。
まず想像で語らず現状の天井を実データ可視化（`ml/analyze/ceiling_distribution.py`）→
**買い目の天井中央値480%・combo は逆オッズ配分で低配当点に厚い**＝保守の正体が判明。
次に「張り方」だけ変える変種を実払戻で backtest（`ml/analyze/bench_ceiling_variants.py`・健全2期間）。

| combo配分 | 中身 | 検証結果（vs 逆オッズ） |
|---|---|---|
| 逆オッズ inverse（旧既定） | wᵢ=1/oᵢ・的中寄りの低配当点に厚い | **ROIもDDも一番悪い** |
| **フラット flat** | wᵢ=1・各点均等 | **ROI +2〜3pt・maxDD -30%・的中率同じ** |
| オッズ比例 odds | wᵢ=oᵢ・高配当点に厚い | **1000%超的中ほぼ倍増**（天井480→1149%）。代償=的中率↓・ROI数pt減・DD振れ大 |
| 三連系だけに集中 | allowed_types=三連 | ROI/的中崩壊・DD膨張 → **不採用** |

★ふくだ判断 A（採用ポリシー）★:
- **通常R（98%）= フラット**。逆オッズは劣るだけ＝ノーコストの地力UP（[[feedback_proactive_debt_paydown]]）。
- **勝負R（2%・高確信）= オッズ比例**。[[payout-ceiling-strategy]]「天井を取る」を高確信レースだけに限定し
  ROI 損失を抑える。集計影響は微小（勝負Rは単勝70%が主役・combo残30%のみ）だが哲学と整合。
- 三連系集中は不採用。

★後知恵ゲートではない★: 全変種が同じ確定オッズで精算され「配分の差」だけを測る。レースを降りない
（[[feedback_odds_gate_hindsight]] の罠と無関係）。本番値（P_prod）= 現状比 ROI 85.2/92.0%（+2〜3pt）・
maxDD 108k/101k（-30%）。実装: `SHOBU_NORMAL_COMBO_ALLOC="flat"` / `SHOBU_SHOBU_COMBO_ALLOC="odds"`
（`bettype_sizing.py`）。scheduler は既定で呼ぶので **bat 編集不要で配線完了**。

★1000%超は「基本方針」にはしない（重要）★: 全レースに odds を効かせると ROI を地味に削る
（黒字化はしない＝S165「買い目工夫では黒字化しない・勝ちはモデルのエッジ次第」を再確認）。
天井狙いは「全レースの方針」でなく「勝負R／将来はキャラ枠 [[character-betting-personas]] に限定」。

## 4. これは「見送りゲート」ではない（前回の罠との違い）

| | 前回 害確定だった見送りゲート | 今回の勝負レート |
|---|---|---|
| 対象 | 買い目**全体**（単複combo） | **単勝という券種だけ** |
| やること | 確定オッズが安いレースを**丸ごと降りる** | 単勝の**張り場を勝負Rに集中** |
| 他レース | 何も買わない | combo は普段どおり買う |
| 罠 | ◎が来て取れた妙味を捨てる | 捨てない（comboは拾う） |

→ 今回は「単勝の張り場の選別」であって「レースを降りる」ではない。
[[feedback_odds_gate_hindsight]] の罠を踏まない。

## 5. 実装方針（将来のためにわかりやすく）

★ふくだ指示「時間かかってもいい・将来のためにわかりやすい実装」★。

### 5.1 レート → per_race_cap の配線（共通の土台）

- `read_per_race_cap()` を「固定3,000円」から「基準金額 × レート」算出に変える。
  - 基準金額 = `daily_start_balance_yen`（既存）。
  - 通常レート = config の新キー `normal_rate_pct`（既定5）。
  - 後方互換: `daily_start_balance_yen` 未設定なら従来の `per_race_max_yen`（3,000）にフォールバック。
- ★この時点では挙動を変えない（5% × 30,000 = 1,500円 になるので、まず現状3,000円との
  差をふくだに見せて合意してから既定値を決める）。

### 5.2 勝負レートの判定と適用

- 勝負条件の判定関数を1箇所に置く（`is_shobu_race(race_eff)` 的なもの・4条件のSSoT）。
  - ★★軸ズレ注意（裏取り済み・最重要）★★: 検証は **rank_w=1（Winモデル◎）** の単勝で
    +9,780円を出した。一方、本番 selection/sizing の軸◎は **composite最強**（W/P/AR混合）。
    cache で測ると **rank_w=1 と rank_p=1 が同一馬なのは35.9%だけ** → composite◎と rank_w◎は
    別馬になりうる。本番がcomposite◎の単勝を厚く買うと検証(+9,780)が再現しない恐れ。
  - → ★勝負レートの単勝は「rank_w=1 の馬」を軸にする（composite◎とは別管理にする）★。
    勝負条件の判定も単勝の対象馬も rank_w◎ で固定する。combo は本番どおり composite◎軸でよい。
- 勝負条件なら per_race_cap を `基準金額 × 勝負レート(15%)` に上げる。
- 勝負Rでは単勝シェアを引き上げる（combo哲学は残しつつ単を厚く）。
  - 具体シェアは実装時に検証で詰める（§3.1 が単勝のみ最良なので、勝負Rは単勝を主役に）。

### 5.3 サイザーの形

- 独立サイザー新設 `shobu_rate` か、`fixed_grade_v2` に勝負レート層を足すかは実装時に判断。
  - わかりやすさ優先なら **独立サイザー新設**（v2 を汚さず、勝負レートの意図が1ファイルで読める）。
  - registry に登録、bat の `--sizing` で切替（v2 はフォールバックとして残す）。

### 6.1 修正（2026-06-20・§3.3 漏れの是正）

★初版の実装は §3.3「通常レートでは単勝を買わない」を満たしていなかった★。非勝負R を
`size_race_fixed_grade_v2` に **そのまま委譲** していたため、v2 が全ティアで出す単勝

- **是正（第1段・S166漏れ）**: 非勝負パスで v2 の返り値から **単勝 leg を除外**（暫定で単勝
  share分は浮かせる）。v2/fixed_grade 本体は不変（registry 経由の素の v2 挙動も不変）。
- **改良（第2段・Session 167）**: ふくだ「通常R は combo しか買わないのだから cap で combo を
  買うのが自然」→ 非勝負パスを ★単勝なしで combo に cap をフルに回す★ に変更（§3.3）。抜いた
  単勝(-EV)分を浮かせず +EV の combo へ。東京2R 1,400→1,600（端数100浮き）。
- **回帰テスト**: `test_normal_race_no_tansho_combo_uses_full_cap`（通常R に単勝/複勝が無い・cap
  内・combo が cap をフルに使う＝素の v2 の combo より厚い・素の v2 は単勝を出す番人付き）。
- **検出経緯**: ふくだ「通常レート買い目に単が入っているのは正しいか」「1,700上限なら combo で
  1,700買うのが自然では」→ コード/設計書/テストの3点照合で、設計書 §3.3 とコード（v2 委譲）・
  テスト（`matches_v2_directly`＝単勝込み一致を固定していた誤テスト）の食い違いが判明。
